# 只读审核规则（--task review 触发）

审核是独立复审轮次：只读，不修改源码；结论基于证据，不基于标题齐全。

## 审查路径（按序执行）

1. **diff 全量**：`git diff` 逐块过；对照声明的验收点，未声明的行为变化单独列出。
2. **加载顺序影响**：改动若触及 `oh-my-zsh.sh`、`lib/*.zsh` 文件名字典序、
   `is_plugin` 判定或 compinit 时序，评估对全部插件/主题的连锁影响。
3. **全局命名空间**：新增别名/函数/全局变量与 367 个插件查重；同名即静默覆盖。
4. **引用与分词**：未加引号的 `$var`、`$(...)` 在空格/空值下的行为；zsh 数组下标
   与 bash 差异；`emulate` 上下文。
5. **tools/ POSIX 兼容**：`sh -n` 之外人工核 bashism；`--unattended` 路径零交互。
6. **补全副作用**：compdef 注册、缓存写入位置（必须 `$ZSH_CACHE_DIR`）、
   compdump 元数据兼容性。
7. **文档一致性**：README 别名表与实现一致；routes.toml 闭集仍成立
   （跑 `python3 scripts/resolve_agent_rules.py --check`）；dev-framework.json
   状态与实际命令一致。
8. **生成物与证据**：chunks.json 是否需再生；声称的测试/截图证据是否真实存在
   且 `images_reviewed: true`。

## 判定基准

- 规范性条款（上游英文注释、别名五准则）不因"看起来过时"而判问题；指控每条
  记录原文位置、实现符号与触发后果，先找反证再定性。
- 测试缺口只对"本次改动引入的新行为"提出；存量缺口记备注不阻塞。
- fork 独有约束（只增不改、.gitignore 标记块、CHANGELOG 双体系）按 development.md
  执行；上游风格问题按 CONTRIBUTING.md 执行。

## 输出格式（固定）

```
## 严重
- <文件:行> <问题> → <建议>
## 中
## 轻
## 结论
三态之一：通过 / 有条件通过（列条件）/ 驳回（列理由）
```

无发现也输出空节与结论，不得省略。
